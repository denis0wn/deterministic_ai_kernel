## 1. NORTH STAR — какую боль рынка решаем

**Боль:** компании в регулируемых отраслях (fintech, risk, healthcare)
не могут внедрять AI для изменения кода, потому что не могут **доказать**,
что изменение: (а) проверено реальными тестами, (б) трассируемо от
находки до патча, (в) не содержит галлюцинаций.

**Продукт:** детерминированный слой верификации и аудита между AI и
production-кодом. LLM — недоверенный вход; все эффекты идут через
kernel-owned границу (`apply_patch_v1` context-verified, `run_tests_v1`
allowlisted); всё хэшируется (BLAKE3), логируется и независимо
верифицируется (evidence chain).

**Позиционирование (уже зафиксировано):** «Deterministic remediation and
audit-trail engine for Python-first risk-critical systems.» Это НЕ
«платформа аудита» и НЕ гарантия отсутствия ошибок. Аудит — сервис вокруг
read-only анализатора + human review + контролируемой ремедиации +
evidence.

## 2. Честное текущее состояние

### Доказанные активы
- Fail-safe гейты: 13 реальных запусков executor — 12 отказов поймано
  ДО любого эффекта, 1 infra-failure; ноль мутаций, ноль fake-success.
- Evidence chain, tamper-evident контракты, readiness-политика,
  negative-acceptance процесс — работают.
- Анализатор находит кандидаты и честно маркирует неуверенность.
- Найдена корневая причина блокера автономной ремедиации (см. журнал).

### Чего пока НЕТ
- **Ни одного зелёного цикла ремедиации.** Продукт доказал безопасность,
  но ещё не доказал полезность (что через конвейер можно реально починить
  баг и получить `chain_consistent_remediation_evidenced`).
- Автономная ремедиация заблокирована: kernel-промпт заставляет модель
  перепечатывать target path (placeholder `<FILE>`); нужен security
  review executor, чтобы это менять.

### Блокеры (честно)
- Модельное качество: текущие локальные модели не выдают well-formed
  патч из-за task-presentation (доказано на 2 семействах, 12/12).
- Executor заморожен; изменения — только через отдельный security review.

## 3. Стратегическое позиционирование (РЕШЕНИЕ)

**Ведём с audit/evidence-слоя, который работает сегодня (human-in-the-loop).
Автономная ремедиация — ускоритель в roadmap, не продукт запуска.**

Обоснование:
1. Evidence-слой доказан; автономная ремедиация заблокирована и
   модель-зависима.
2. Регулируемый покупатель покупает аудит и трассируемость, не «магию».
3. Для продажи не нужна идеальная модель — нужен заслуживающий доверия
   конвейер. Он заслуживает.
4. Это снимает главный пробел: первый настоящий зелёный цикл.

## 5. Анти-дрифт механизмы
1. **Единый источник правды:** этот файл; читается первым в каждой сессии.
2. **Drift-check:** перед любой задачей — «двигает ли она DoD текущей
   фазы?» Нет → не делаем (или в журнал решений как отклонение).
3. **Definition of Done бинарно и измеримо** для каждой фазы.
4. **Журнал решений** ниже: стратегические выборы фиксируются и не
   пересматриваются без новой записи.
5. **Каждая фаза = коммит + запись в `/tmp/dek_ai_matrix/`.**
6. **Запрет научных экспериментов вне фазы:** эксперименты допустимы,
   только если они двигают DoD текущей фазы. mq1–mq5 закрыты.

## 6. Инварианты (неизменяемы, поверх любой фазы)
- LLM — недоверенный вход; никакого shell/fs/network из LLM-текста.
- Все эффекты — только через kernel-owned границу.
- Fail-closed валидация; галлюцинированный контекст отвергается.
- Human review обязателен перед ремедиацией.
- Никаких production deployments; никаких customer/private данных.
- Анализатор read-only к сканируемому workspace.
- Никакого seed-hunting; бюджет попыток фиксируется заранее.
- `chain_incomplete`/`tests_failed`/`fail_closed` — честные результаты.
- Никаких commit/reset/stash/push без явного разрешения.
