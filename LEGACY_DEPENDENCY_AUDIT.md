# Legacy Dependency Audit: deterministic_ai_kernel

В данном документе приводится полный аудит всех оставшихся зависимостей ядра от унаследованных концептов workflow engine (`StepKind`, `TaskClass`, `build_steps`) с классификацией по категориям:
* **A) Можно удалить сразу** — зависимости, которые не влияют на публичные API ядра и могут быть стерты.
* **B) Нужен адаптер** — зависимости, требующие временного фасада совместимости перед удалением.
* **C) Часть внешнего API** — публичные контракты, используемые внешними тестами или CLI-командами.

---

## 1. Зависимости от `TaskClass`

* **`src/workflow/contract.rs`** (Объявление `pub enum TaskClass` и таблицы `flow_table`)
  * *Классификация:* **C) Часть внешнего API**.
  * *Описание:* Используется интеграционными тестами для создания задач и компиляции по умолчанию.
  * *Стратегия:* Сохранить как фасад совместимости; перевести тесты на передачу сырых `ExecSpec`.

* **`src/workflow/compiler.rs`** (Метод `Workflow::task_class`)
  * *Классификация:* **B) Нужен адаптер**.
  * *Описание:* Используется для маппинга `TaskInput` на старые типы задач.
  * *Стратегия:* Заменить на прямую компиляцию в `ExecSpec` без промежуточного определения `TaskClass`.

* **`src/exec_spec.rs`** (Тестовая зависимость от `TaskClass::to_exec_spec`)
  * *Классификация:* **A) Можно удалить**.
  * *Описание:* Используется в юнит-тестах для верификации генерации спецификации.
  * *Стратегия:* Переписать тесты на создание спецификаций вручную или через `ExecSpec::new`.

---

## 2. Зависимости от `StepKind`

* **`src/workflow/contract.rs`** (Объявление `pub enum StepKind`)
  * *Классификация:* **C) Часть внешнего API**.
  * *Описание:* Используется внешними инструментами для диспетчеризации конкретных шагов.
  * *Стратегия:* Перевести исполнение на `PrimitiveKind`; StepKind оставить как legacy-адаптер для внешнего CLI.

* **`src/worker.rs`** (Функции `parse_step_kind_from_step_id` и `required_capability_for_step`)
  * *Классификация:* **B) Нужен адаптер**.
  * *Описание:* Служат fallback-механизмом проверки capabilities, если ExecSpec не содержит ограничений.
  * *Стратегия:* Сохранить как fallback до полного перехода всех тестов на ExecSpec.

* **`src/effects.rs`** (Маппинг строковых ID шагов на `StepKind`)
  * *Классификация:* **B) Нужен адаптер**.
  * *Описание:* Используется для обратной совместимости при вызове эффектов.
  * *Стратегия:* Полностью перевести на исполнение через провайдеров по типам примитивов (`Compute`, `Read`, `Write`).

---

## 3. Зависимости от `build_steps`

* **`src/workflow/compiler.rs`** (Метод `Workflow::build_steps`)
  * *Классификация:* **A) Можно удалить**.
  * *Описание:* Используется внутри компилятора для генерации векторов шагов.
  * *Стратегия:* Переписать компилятор на генерацию структуры `ExecSpec` напрямую, минуя метод `build_steps`.

* **`tests/scheduler_integration.rs`** (Вызовы `Workflow::build_steps`)
  * *Классификация:* **A) Можно удалить**.
  * *Описание:* Используется в тесте для генерации тестового набора шагов.
  * *Стратегия:* Переписать тесты на генерацию шагов через `ExecSpec`.
